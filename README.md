# Интеллектуальная аналитика звонков контакт-центра МФЦ РУДН

> **Кейс №6:** Разработка интеллектуального помощника руководителя контакт-центра Многофункционального центра Российского университета дружбы народов (МФЦ РУДН).

Проект автоматизирует контроль качества консультаций, транскрибирование и семантическую классификацию телефонных обращений абитуриентов, родителей, студентов и сотрудников университета с привязкой к интервальным показателям телефонии Avaya CMS.

---

## 🎯 Цели и задачи решения

1. **Распознавание и диаризация речи:** Преобразование аудиозаписей диалогов оператор–клиент в текст с таймкодами и ролями.
2. **Классификация обращений:** Определение тематики звонка, категории заявителя (абитуриент РФ, иностранец, родитель, студент), характера запроса и целевого подразделения РУДН.
3. **Контроль качества по 6 обязательным критериям:**
   - **Понимание вопроса:** Выявление неоднозначностей, учет статуса заявителя.
   - **Точность информации:** Сверка ответов оператора с действующими эталонными регламентами и приказами РУДН на дату звонка.
   - **Полнота ответа:** Проверка обязательного чек-листа (сроки, документы, контакты, способы подачи).
   - **Маршрутизация:** Обоснованность и корректность переводов в профильные подразделения (ПК РФ, ПК для иностранцев, Бухгалтерия, Общежития, Деканаты).
   - **Стандарты коммуникации:** Соблюдение этики, вежливости, скриптов приветствия/прощания, выявление раздражения и прерываний.
   - **Результат консультации:** Фиксация исхода (решен в звонке, предоставлен следующий шаг, переведен, открыт).
4. **Выявление системных проблем и формирование мер:**
   - Кластеризация повторяющихся затруднений и вопросов заявителей.
   - Обнаружение информационных пробелов на сайте и в FAQ.
   - Автоматическая генерация управленческих мер (Action Plan) с назначением владельца (МФЦ, Приёмная комиссия, ИТ-департамент) и целевых метрик эффекта.
5. **Интерактивный дашборд руководителя:**
   - **Обзор:** Сводка нагрузки CMS (предложено, отвечено, сбросы, ASA), распределение тем и категорий заявителей.
   - **Очередь проверки:** Фильтрация по критическим ошибкам, темам, статусам модерации и режимам нагрузки.
   - **Карточка звонка:** Синхронизированный плеер, стенограмма с кликабельными таймкодами, доказательная база нарушений с цитатами и эталонами, журнал решений руководителя.
   - **Системные меры:** Трекер поручений по устранению корневых причин ошибок.
   - **Тест-стенд:** Интерактивная проверка произвольных диалогов в реальном времени.

## 📊 Решение проблемы отсутствия первичных данных

Поскольку реальные аудиозаписи и выгрузки CMS находятся на согласовании в защищённом контуре университета, в систему интегрирован **высокоточный калиброванный генератор**, основанный на нормативных документах приёмной кампании РУДН 2026 года и методологии исследования:

- **Интервалы Avaya CMS:** 30-минутные слоты с 9:00 до 19:00 (июнь — август 2026 г.) с выделением пиковых дедлайнов (20.06, 10.07, 25.07, 04-05.08, 18.08, 24.08), расчетом очередей, отказов, позиций операторов и ASA.
- **Калиброванные сценарии с доказательной базой:**
  1. `CALL-2026-0804-001` (Критическая ошибка): Оператор назвал срок согласия «до вечера 5 августа, до 18:00» вместо официального регламента «5 августа строго до 12:00 МСК».
  2. `CALL-2026-0821-002` (Неполный ответ): Заявителю назван стандартный срок оплаты «10 дней», скрывая жесткий дедлайн платного набора 24 августа 12:00 МСК.
  3. `CALL-2026-0715-003` (Ошибочный канал): Иностранного абитуриента без СНИЛС направили на Госуслуги РФ вместо международного портала `intstudent.rudn.ru`.
  4. `CALL-2026-0726-004` (Повторное обращение): Абитуриент не видит себя в списках из-за регламентной задержки синхронизации ЕПГУ (до 24 часов).
  5. `CALL-2026-0801-005` (Срыв стандартов): Грубость оператора и сброс звонка в час пик.
  6. `CALL-2026-0710-006` (Эталонная консультация): 100% соблюдение стандартов по общежитию и медсправкам (086/у, флюорография).
  7. Корпус из 30+ звонков по всем направлениям (ДВИ, квоты СВО/БВИ, маткапитал, справки МФЦ).

## 🔒 Безопасность и 152-ФЗ

- **Псевдонимизация:** Идентификаторы заявителей и телефоны хэшируются устойчивым алгоритмом (`Заявитель_xxxx`).
- **Минимизация данных:** Не сохраняются чувствительные персональные данные и биометрия голоса.
- **Проверяемость автооценки:** Любая оценка сопровождается точной текстовой цитатой, таймкодами и ссылкой на пункт регламента.

## 🚀 Запуск и использование

### 1. Требования
- Python 3.10 или выше
- Установленные библиотеки (FastAPI, Uvicorn, Pydantic)

### 2. Запуск веб-дашборда
```bash
python run.py
```
После запуска откройте в браузере:
- **Дашборд руководителя:** `http://127.0.0.1:8000`
- **Документация OpenAPI / Swagger:** `http://127.0.0.1:8000/docs`

### 3. Запуск тестов
```bash
python -m pytest tests/ -v
```
